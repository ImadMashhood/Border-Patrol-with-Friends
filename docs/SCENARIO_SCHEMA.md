# Scenario authoring contract, version 1

`assets/scenarios/*.json` is loaded into the Rust Scenario structure. Each manifest contains schema_version, scenario_id, seed, character (name, biography, occupation, speech_style, emotion_baseline), truth (purpose, itinerary, cargo, smuggling, documents), public_claims (id/text), evidence (id/description/reveal_condition/location/reveal_rule), metadata (compatible occupation/reason/cargo category and canonical document fields), contradictions (claim_id/evidence_id/explanation), allowed_actions, opening_line, resolution_rules, and actor (topic responses and personality reactions).

Evidence is either `documents` (presented at the driver) or `secondary` (revealed by a physical search at its specific location). Requesting secondary does not reveal evidence. Locations are `documents`, `glovebox`, `cargo`, `container` and `trailer`; container and glovebox searches require their access panel to be opened first. Actor facts use `purpose`, `itinerary`, `cargo`, public claim IDs and evidence IDs. Secondary fact IDs are forbidden until inspected. Honest travelers can describe their own cargo. Smugglers know the truth but use the cover account until they choose to concede or are confronted; public cargo claims remain usable before inspection. Live smugglers react to specific evidence confrontation; confessions are optional and dispositions never require one. Only initial purpose/itinerary/cargo cover fields enter the live prompt. Repeat, irrelevant and confront response strings are reserved for offline rehearsal. Truth stays internally consistent; the deliberately false public claim creates the discoverable contradiction.

Validation rejects wrong schema version, empty required facts, duplicate case/claim/evidence IDs, dangling contradiction references, unsupported actions and honest cases with contradictions. The pack must contain exactly ten unique cases and exactly three smugglers. One fixed seed controls pack order without replacement. `assets/case_templates.json` also validates occupation/reason/cargo compatibility and legal status; canonical document identity, purpose, itinerary and cargo must match truth. Duplicate traveler names are rejected.

Character records now include `authority_response` (eager, pragmatic, opportunistic, playful, reluctant, principled, defiant) and `compliance_bounds`. These govern spoken reactions to officer demands. Innocent travelers can make pressured verbal denials without becoming smugglers; principled/defiant travelers can have hard boundaries against such denials. Actual cargo, documentary evidence, guilt and dispositions are immutable. An omitted authority response defaults to principled behavior, but manifests still require the canonical metadata and evidence reveal rules.

The host generates `record_seed` and character `variation` before the interview. `observation_scope` is a private host-to-caller marker: the evidence list has already been reduced to physically observed IDs, so a searched glovebox can be discussed before a cargo search. Authored packs cannot set that marker to pre-disclose evidence. Runtime observations and personality state do not mutate truth. See [Parts 7–10](PARTS_7_10.md).

## Character psychology and trusted physical context

`character.psychology` has 0–100 traits: `survival`, `boldness`, `integrity`, `aggression`, `sociability`, `greed` and `pride`. All ten authored travelers have individual values. Defaults keep older packs loadable. Runtime `encounter` observations (weapon drawn/aimed, injury, nearby violence, speaking officer) are supplied by the host, never a client claim. Each remembered turn retains its physical context and officer identity. Dialogue emotion also accepts `afraid`, `panicked` and `desperate`. Coerced speech cannot change material facts, documents, evidence, disposition or money. See [psychology contract](CONVERSATION.md).
